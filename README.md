## ⭐ Featured Projects

### ⭐ Project 01 — Meeting Follow-up Automation

**What it solves:**
Turns unstructured meeting notes into a clear follow-up with the action item, the owner, and the deadline, and handles the cases where information is missing.

**Tools:**
Google Forms · Zapier · AI by Zapier · Paths by Zapier · Google Sheets · Gmail

**My role:**
I chose the problem and designed the workflow: meeting notes are submitted through a form, AI extracts the key fields (action item, owner, deadline, meeting summary, missing information, request status), and the flow then splits into a valid path, which logs a row and sends a follow-up email, and a fallback path, which alerts the organizer to complete the missing details.

🔗 [View Project](./01-Process%20%26%20Data%20Thinking/Independent-Project)

---

### ⭐ Project 02 — PlanCraft AI

**What it solves:**
Turns a rough project idea into a structured action plan (summary, goal, phases, recommended actions and risks) that is saved and shown to the user with a status.

**Tools:**
Lovable · Supabase · n8n Cloud · Webhooks · Google Gemini

**My role:**
I built the integration between three systems: a Lovable interface that saves each request, a Supabase database that stores requests and plans, and an n8n workflow that receives the request through a webhook, generates a structured plan with an AI agent, saves it, and updates the request status so the app can show the result.

🔗 [View Project](./06-Automation%20%26%20Integration%20Thinking/Course-Project)

---

### ⭐ Project 03 — UX Review Agent

**What it solves:**
Gives UX/UI designers a fast, structured first review of a design brief or screenshot through Telegram, and refuses or escalates when a request is outside its limits.

**Tools:**
n8n · Telegram · Google Gemini · n8n Data table

**My role:**
I designed the agent's behavior and boundaries: it reviews only when it has the platform, users and goal, asks for what is missing, saves a review only after a clear yes with an insert-only tool, and sends delete or edit requests to a human. I ran eight test scenarios, found and fixed behavior problems, and documented the results.

🔗 [View Project](./05-Control%20Its%20Agency)

## 💡 Key Lessons

Throughout the course, I learned that building with AI is not simply about generating outputs.

It is about:

- Understanding the real problem
- Designing before building
- Choosing the right level of automation
- Knowing where AI should and should not be used
- Controlling AI behavior
- Testing assumptions
- Handling failure
- Connecting systems
- Evaluating results
- Improving continuously

### My Most Important Lesson

**A system that runs is not a system that works.**

The same moment kept repeating across the units: a screen looked finished, an answer sounded right, a workflow showed green checks, and only testing showed what was really happening. An assistant cited the right source but gave no steps. A request was accepted, but the work was not complete. An AI answered confidently from a document it never retrieved.

So I learned to ask for the evidence before I ask whether it works, to separate what I verified from what I assumed, to give an AI the least power it needs, and to design for failure before it happens. The goal is not to make AI answer. It is to understand how it answers, and to be able to prove it.
